The four directions

Each one takes a different position on how much of the search the AI should take over.

01
Modal / Sidebar Takeover
Filtering is a mode you enter. Ask in English or drill three levels of menu, then apply. The reviewed design, rebuilt as the baseline.
02
Miller Columns
The taxonomy opens sideways, column by column, with a count on every value and the results beside it. An agent drives the same columns.
03
Text Input Field
One sentence becomes the query, written back as editable English. A toggle swaps the same clauses into conventional filters.
04
Sidebar Agent
No filter surface. You filter from the grid's column headers while an assistant proposes changes to the same grid.

What good looks like

Your measures from 14 September. Every option in this deck is scored against them.

G1 · Quick screen
About 70% of queries use three fields or fewer. They need a cold start that reaches a usable list fast.
G2 · Refine
The 30% that get refined need cheap, reversible changes without starting over.
G3 · Deep Boolean
About 10% of refined queries, from your largest accounts. They need AND, OR and NOT across attributes.
Clicks
How many it takes to reach a usable list.
Speed of access
How long before the first results appear.
Three terms
70% of queries reachable in three terms or fewer.
Power beneath
Depth for the 10% without slowing down the 70%.

The failure mode is an interface that serves one goal and abandons the others, or serves them as two products bolted together.

01 Modal / Sidebar Takeover

For
  • +AI and hand-built filters write into one builder, so a pill the AI wrote reopens the same picker path.
  • +A count sits beside every value before you commit.
  • +The applied query stays editable from the bar without reopening the modal.
  • +Boolean appears as visible controls, not typed syntax.
Against
  • —A cold start costs 3n + 3 clicks, level with the live platform. Fails G1.
  • —The modal hides the table, and the total only appears after Apply.
  • —Three stacked cascade levels, with one branch open at a time.
  • —OR between groups is drawn but ignored, and nothing nests. Fails G3.
  • —A second question replaces the query instead of refining it.

Verdict: suits G2, nudging a list you already have. Filtering as a mode hides the results it filters.

02 Miller Columns

For
  • +The path stays on screen and nothing is wiped.
  • +Every attribute and value carries its count. Six clicks to a three-field list, against 13 to 16 today.
  • +No commit step, so the count, pills and table cannot disagree.
  • +The agent drives the real columns, one undoable step at a time.
Against
  • —No quick cold start: the composer sits below the taxonomy. Your objection, and it holds.
  • —Nothing sequences the task for a first-time user.
  • —Tested at about half the real attribute density.
  • —Attributes are hard-ANDed, so cross-attribute OR and nesting are out. G3 is not served.

Verdict: the strongest structure and the weakest opening. Move the composer to the front so a sentence lands in the columns.

03 Text Input Field

For
  • +Zero clicks to a first list. The composer is focused on arrival.
  • +The prompt resolves into visible, editable controls.
  • +A correction costs two or three clicks, with one undo per edit.
  • +The Filters view draws the same query, so switching loses nothing.
Against
  • —It misreads queries in ways that look correct: "non-generic drugs" came back as "Generic drugs".
  • —A blank input teaches nothing about the roughly 27 attributes.
  • —Nested Boolean is flattened without warning. Fails G3.
  • —There is no way to refine from the results grid.

Verdict: the right front door for the 70%. It needs per-clause provenance and a builder behind it before the 10% can rely on it.

04 Sidebar Agent

For
  • +The only direction that stops the grid running off the screen, and it works under any of the others.
  • +Two clicks per parameter, with counts before you commit.
  • +The assistant proposes, previews the row count, applies, and leaves a receipt with undo.
  • +Column management the live product lacks: hide, move and pin.
Against
  • —It starts from every row rather than a screen. Your objection. Fails G1.
  • —BI assistants have the weakest retention record here. Tableau retired Ask Data in 2024.
  • —You can only filter the columns on screen.
  • —OR within a column and AND across columns, with no NOT. Fails G3.

Verdict: adopt the grid redesign whichever model wins. The results-first filtering model fails the cold start as built.

What we need you to decide

01
Which front door?
A sentence that resolves into structure (Option 3), or a browsable taxonomy with a sentence in front of it (Option 2).
02
Does the grid redesign go in regardless?
Option 4's results view answers a complaint the others leave alone, whichever filtering model wins.
03
How much Boolean do the 10% need?
None of the four expresses nested, cross-attribute logic yet. Tell us what your largest accounts actually build.
04
Where we would go next
Fuse Options 2 and 3: a composer in front that lands in the columns, with a group builder underneath for the 10%.
