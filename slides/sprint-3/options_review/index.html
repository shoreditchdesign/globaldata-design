Four directions for
natural-language search

Sprint 3 options review. Four interactive prototypes, the strengths and limitations of each, and a direct link to every state.

GlobalData × Shoreditch · 16 September 2026

The four directions

Each direction takes a different position on how much of the search the AI should handle.

01
Modal / Sidebar Takeover
Filtering is a separate mode. The user asks in plain English or selects through three menu levels, then applies. This is the previously reviewed design, rebuilt as the baseline.
02
Miller Columns
The taxonomy opens sideways, one column per level, with a count on every value and results alongside. An agent can operate the same columns.
03
Text Input Field
A typed sentence becomes the query, shown back as editable text. A toggle presents the same conditions as conventional filters.
04
Sidebar Agent
There is no separate filter panel. Filters are set from the column headers of the results grid, and an assistant proposes changes to the same grid.

Three user goals

Based on 176,404 advanced searches across the Drugs and Clinical Trials databases.

G1
Quick screen
53% of searches use a single filter and 85% use three or fewer. A usable list has to be reachable in very few steps.
G2
Refine
80% of follow-up searches keep the same fields and change a value. Only 12% add a filter. Adjusting a known query has to be fast and reversible.
G3
Deep Boolean
15% of searches use four or more filters, with up to 22 in one search. OR within a field appears in 19%, NOT in under 1%.

Source: GlobalData advanced search usage extract, 1 May to 21 August 2026. Shares are of searches, not users.

Four measures

Each direction is assessed against the same four measures.

01
Clicks
The number of clicks from a cold start to a usable list.
02
Speed of access
The time from the first action to results on screen.
03
Three terms
Searches of three filters or fewer, which account for 85% of the total, are completed quickly.
04
Power beneath
Depth for complex queries is available without adding steps to simple ones.

01 Modal / Sidebar Takeover

For
  • +Natural-language and manual filters write into one builder, so an AI-generated filter reopens in the same picker.
  • +Every value shows its result count before it is selected.
  • +Applied filters remain editable from the filter bar without reopening the modal.
  • +Boolean logic is presented as visible controls rather than typed syntax.
Against
  • —A three-filter search takes 12 clicks by hand, level with the current platform. Does not meet G1.
  • —The modal covers the results, and the total appears only after Apply.
  • —Values sit three menu levels deep, with one branch open at a time.
  • —OR between groups is displayed but not applied, and groups cannot be nested. Does not meet G3.
  • —A follow-up question replaces the query rather than refining it.

Verdict Best suited to G2, adjusting an existing list. Filtering as a separate mode hides the results being filtered.

02 Miller Columns

For
  • +The selection path stays on screen, and earlier choices are never cleared.
  • +Every attribute and value shows a live count. A three-filter search takes 6 clicks.
  • +There is no apply step, so the count, filters and table always agree.
  • +The agent operates the same columns, one reversible step at a time.
Against
  • —There is no fast entry point. The composer sits below the taxonomy, so a first search begins by browsing.
  • —The interface gives a first-time user no clear sequence to follow.
  • —Tested at roughly half the production attribute count, 15 of 27.
  • —Attributes combine with AND only, so cross-attribute OR and nesting are unavailable. Does not meet G3.

Verdict The strongest structure and the weakest entry point. Placing the composer first would let a sentence resolve directly into the columns.

03 Text Input Field

For
  • +A first search takes zero clicks. The composer is focused on arrival and Enter submits.
  • +The query resolves into visible, editable controls.
  • +Correcting a value takes two to three clicks, with one undo step per edit.
  • +The Filters view renders the same query, so switching views loses nothing.
Against
  • —Some queries are misread in ways that appear correct: "non-generic drugs" resolves to "Generic drugs".
  • —An empty input does not reveal the roughly 27 attributes available.
  • —Nested Boolean cannot be expressed and is flattened without warning. Does not meet G3.
  • —Results cannot be refined from the grid.

Verdict The strongest entry point for G1. It needs clause-level provenance and a group builder before it can support G3.

04 Sidebar Agent

For
  • +The only direction that keeps a wide results grid usable, and it can sit beneath any of the other three.
  • +Two clicks per filter, with counts shown before selection.
  • +The assistant proposes a change, previews the row count, applies it and records an undo.
  • +Adds column management that the current platform lacks: hide, reorder and pin.
Against
  • —The user starts from the full dataset rather than from a search. Does not meet G1.
  • —BI assistants have a weak retention record. Tableau retired Ask Data in 2024.
  • —Only the columns currently on screen can be filtered.
  • —OR within a column and AND across columns, with no NOT. Does not meet G3.

Verdict The grid redesign is worth adopting whichever filtering model is chosen. Results-first filtering does not support a fast first search as built.
