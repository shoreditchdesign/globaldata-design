01 — What changed

Advanced search

In the last round, testers did not find Advanced search. An Advanced filter switch now replaces the Quick and Advanced tabs.

  • +Inside the search fieldThe switch sits in the search field on the start screen and in the composer on the results page.
  • +One control, two modesOne on/off switch replaces two tabs. The field stays in place, and only the area under it changes.
  • +Miller columns under the fieldWith the switch on, the Miller columns show three at a time, with the filter box below them.

01 — What changed

Loading states

In the last round, testers could not tell whether a search had run. The prototype now shows its work.

  • +A loading state on the tableThe table shows a loader after every search and after every filter change.
  • +The Miller columns walk to the queryWhen a typed query resolves, the columns move through each attribute in turn.
  • +The table does not waitThe filters apply before the walk starts, so the table never waits for it.
Screenshot

01 — What changed

Results layout

The results page is now one grid. A chat panel sits beside the table, under the filter row.

  • +A chat panel beside the tableThe commonly used filters head the panel. The query field sits at its foot, as a chat composer does.
  • +A collapsible panelA toggle in the footer folds the panel away to the side, and opens it again.
  • +One status barThe count, Columns and Export run across both the panel and the table.
Screenshot

01 — What changed

Other changes

  • +A labelled Add filterThe button reads “+ Add filter” and opens the full field list.
  • +A filter row of three linesThe filter row stops at three lines. The remaining filters fold into a count that opens a popover.
  • +Tick boxesEach value shows a tick box. Clicking the row selects only that value, and clicking the box adds it. Unticking a value removes it.
  • +An empty state with recoveryWhen a search finds nothing, the table names the filter to remove and offers two actions.
  • +Column filtersEach column head shows a count of its applied values. A change made from a column writes back to the filter row.

02 — User testing plan

Setup

Control — Idea 1b
  • ·Last round’s Prototype 1, with no changes.
  • ·Lyssna test “GlobalData Sprint 5 user testing control”.
  • ·Its scores are the baseline for the comparison.
Revised — Idea 1c
  • ·Idea 1b with the changes in this deck.
  • ·Lyssna test “GlobalData Sprint 5 user testing”.
  • ·Higher scores than the control show that the changes work.

Both tests ask the same eight questions and are drafted in Lyssna. Only the prototype link differs, and each test has its own link. The audience is the wider internal group of approximately 35–40 people that Harriet Osmond has lined up.

Analysts reach a usable list of drugs with less effort when they can describe the search in their own words, refine it in place, and switch to building it by hand without having to look for the option.

02 — User testing plan

Questions

Seven tasks, then NPS. Tasks 1 to 3 repeat the last round word for word. Task 4 no longer names the builder. Tasks 5 to 7 are new.

Task 1 G1
Find all Phase III drugs in Europe that act on Janus Kinase.
Task 2 G2
Change the last search. Replace Europe with the United States.
Task 3 G3
Use plain language to find a set of five filters.
Task 4 G3
Find the same drugs again. Choose each filter by hand.
Task 5 G2
Remove the route of administration from the search.
Task 6 G2
Show only the drugs from one company in the list.
Task 7
Find Phase I gene therapies for dermatology in Brazil. If there are no results, change the search.
NPS
How likely is the tester to recommend this way of searching to a colleague?

02 — User testing plan

Measures

Each measure compares Idea 1c with the control.

1–5
Ease per task
1 is Very difficult and 5 is Very easy. Scored after each of the seven tasks.
0–10
NPS
0 is Not at all likely and 10 is Extremely likely. The standard NPS scale.
Why
Reasons
A free-text reason after every score. The reasons show which problems remain.
T4
Discovery
Task 4 asks testers how they went about it. The answers show whether they found Advanced filter without a prompt.

Every scale now runs from negative on the left to positive on the right. In the last round, about half the testers read the reversed scales backwards, so those scores do not compare. This round sets the baseline.

02 — User testing plan

Hypothesis per change

A change works if its task scores higher in Idea 1c than in the control, and the reasons no longer mention the problem.

Advanced filter switch T4
Most testers describe turning on Advanced filter without having to look for it.
One switch for the mode T4
No tester is unsure which mode is on.
Tick boxes T2
Task 2 scores higher, and is the easiest task in Idea 1c.
Removing values T2, T5
No reason says that a value or a filter could not be removed.
Three-line filter row T3, T4
No reason says that the filters push the results away.
Loading state All
No reason says that the search did not appear to run.
+ Add filter T6
Task 6 scores higher, and the reasons mention Add filter.
Column filters T6
The reasons show whether testers start at the filter row or at the columns.
Empty state T7
Task 7 scores higher in Idea 1c than in the control.

One check has no change yet: whether testers still confuse Target and Mechanism of action, in Tasks 1 and 4.
