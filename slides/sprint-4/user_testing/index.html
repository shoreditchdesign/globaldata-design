User testing session

You've been invited to take part in a short test for GlobalData Healthcare. The exercise is a few search and filter tasks in an interactive HTML prototype.

GlobalData × Shoreditch · 24 September 2026

Context

As part of our design engagement, we are working with GlobalData Healthcare to prototype directions for advanced search in the Drugs database, built around natural-language input.

In today's session we will test these ideas and compare the outcomes of two parallel directions, each combining natural-language search with the advanced search in its own way.

Three user goals

From 176,404 existing advanced searches across the Drugs and Clinical Trials databases, we narrowed the work down to three user goals.

G1
Quick search
53% of searches use a single filter and 85% use three or fewer. A usable list has to be reachable in very few steps.
G2
Refined search
80% of follow-up searches keep the same fields and change a value. Only 12% add a filter. Adjusting a known query has to be fast and reversible.
G3
Power search
15% of searches use four or more filters, with up to 22 in one search. OR within a field appears in 19%, NOT in under 1%.

Hypothesis

A search that starts as a sentence and resolves into a visible, editable query gets analysts to a usable list with less effort than building the same filters by hand, and makes changing that search easier still.

01
A quick search lands first time (G1 · Task 1)
Phase III, Europe and Janus Kinase, typed as one sentence, return the right list without the tester rewriting the query.
02
Refining is the easiest task of the four (G2 · Task 2)
Swapping Europe for the United States is an edit to the query already on screen, so it scores easier than building the search did.
03
Their own words resolve to what they meant (Task 3)
Testers read the results rather than rephrasing. Where a phrase can't be placed, saying so keeps their trust in the rest of the query.
04
By hand is harder, and one layout is easier to navigate (G3 · Task 4)
Building the same search in the advanced search scores harder than typing it. Across the two prototypes, the scores show whether Miller columns or the file tree makes a filter easier to find.

Measured by a 1–10 difficulty score and its reason after each task, and a 0–10 recommendation score at the end. The test runs twice, once per prototype, so the scores compare directly.

Instructions

01
Think out loud
We will record your screen and your clicks, but it helps to hear your thoughts throughout. Say what you're thinking as you go.
02
There are no wrong outcomes
There are no wrong answers, and we're not testing you. We're testing whether the search makes sense. If something is confusing or annoying, that's the most useful thing you can tell us.
03
This is a prototype
Parts of it are real and parts aren't. The drug data is illustrative and only some paths are built. If you hit something that doesn't respond, tell us what you expected it to do, and carry on.
