Feedback from the last review

01
Filter language undersells the action
Users are searching for something specific rather than reducing a dataset, and the language should reflect that intent. Apply filter is replaced by a search field carrying example prompts.
02
Two mental models
Search-first users describe what they want; browse-first users expect to see the set and refine it. Both are presented for GlobalData to choose between.
03
Natural language has to land as structure
A typed query should resolve into a structured, editable query rather than an opaque answer. AVA is already in use across ICS with positive client feedback, and AlphaSense remains the AI-first competitor.
04
A mixed audience
Data engineers who build filters by hand sit alongside less technical users. A single interaction pattern is unlikely to serve both.
05
The grid's own capabilities
AG Grid is already decided and provides sorting and column search. Grouping is proposed to two levels, industry then sub-industry.

Option 2 Overview

Three ways to search — a typed sentence, a row of quick filters, and the full filter tree — each building the same visible, editable query.

The screen opens on the text box with the results table empty beneath it, so a quick search is one typed line and Enter (G1 + 2). Explorer opens the filter tree beside the table for deeper searches (G3).

Once results are shown, each filter remains editable where it was chosen: values can be ticked and unticked, is flipped to is not, or a condition cleared with its ×, and the table updates as the change is made (G2).

Counts in the prototype run against a fixed sample of 1,440 drugs. Thirteen of the twenty-seven Drugs attributes are wired.

Option 2 — How it addresses Goal 1

G1
Quick screen
53% of searches use a single filter and 85% use three or fewer. A usable list has to be reachable in very few steps.
A typed sentence, or three clicks

The search is typed in the user's own words and submitted with Enter. The box is focused on arrival, so a three-filter search costs a single click. Typing completes against common queries, and any phrase the resolver cannot place is reported rather than assumed.

For users who prefer to click, the quick filters sit directly beneath the box. A single filter takes three clicks: open it, tick a value, Resolve. That covers the 53% case without opening the tree.

Option 2 — How it addresses Goal 2

G2
Refine
80% of follow-up searches keep the same fields and change a value. Only 12% add a filter. Adjusting a known query has to be fast and reversible.
Editing in place

Swapping a value takes three clicks — untick, tick, apply — in the same place it was chosen. Removing one takes a single click on its × in the sentence, and the table updates immediately. Undo reverses any change, one step at a time.

Every value carries the number of drugs it would leave, so the effect of a change is visible before it is made. Adding a fourth filter takes three clicks, the same as the first.

Option 2 — How it addresses Goal 3

G3
Deep Boolean
15% of searches use four or more filters, with up to 22 in one search. OR within a field appears in 19%, NOT in under 1%.
OR by default, NOT at no extra cost

Two values ticked in one branch read as Phase II or Phase III. No operator has to be chosen, so the first boolean condition takes four clicks, including Apply.

Option-clicking a box excludes a value instead, at no additional cost. One attribute can hold both — Molecule Type is Small Molecule but is not Peptide — in five clicks, and the sentence reads in those terms.

Option 2 — Weighed up

For
  • + Three ways in, one query (G1 + G2)A typed sentence, the filter chips and the tree all write the same query, and the box reads it back in plain words.
  • + Nothing is committed unseen (G1)Every value carries the count it would leave, so the result is known before the query runs rather than after it.
  • + Exclusion costs no extra click (G3)Option-clicking a box excludes the value, and one attribute can keep some values and drop others in a single clause.
Against
  • − Deep queries remain manual (G3)Four filters take nine clicks in the tree, and the 22-filter searches the usage data records would take considerably more.
  • − Nothing is saved (G2)Saved searches are not yet supported, so returning to a previous query means rebuilding it.

Option 2 — The detail

Smaller decisions, each worth a moment in the prototype.

  • +A resolved query lands in the treeThe branches it was read from open, and the values tick in sequence.
  • +The box completes the queryCommon queries complete as they are typed, and Tab accepts the remainder.
  • +$$ inserts a worked exampleSix examples cycle, for demonstrations and for users new to the vocabulary.
  • +Excluded values carry a minusThe value remains chosen, marked in the negation tone rather than appearing unticked.
  • +Duplicate clauses fold togetherFlipping is not back to is merges the two clauses into one.
  • +The record opens over the queryThe full record opens from the right over a scrim, and closes if an edit removes that drug from the results.
