# Sprint 3 — decisions

Log of deliberate divergences from the Paper source, and why.

| Date | Decision | Rationale | Affects |
|------|----------|-----------|---------|
| 2026-09-04 | Restyle to shadcn tokens rather than reproduce the Paper palette and type (DM Sans / Plus Jakarta Sans). | The brief is an uplift pass — structure ported, surface raised to the design system. | Idea 1, all screens |
| 2026-09-04 | Prototypes are static and hardcoded. No filter engine, no data fetching, no state beyond click-through. | Exploratory sprint, not a production build. Keeps 3 ideas × N screens affordable. | All ideas |
| 2026-09-04 | Idea 3 must not be a chat. The source AI tab already renders a transcript, so a conversational design would have duplicated the incumbent rather than explored past it. | The direction has to test something Idea 1 does not already do. | Idea 3 |
| 2026-09-06 | Prototype screens render full bleed at viewport height; all navigation moved into a floating Explorer (Cmd/Ctrl+Shift+E). No breadcrumb, frame, stepper or footer. | The source screens are a product, not a slide — a visible harness undercuts the review. The Explorer is `fixed`, so it never reflows the screen. | All ideas |
| 2026-09-06 | `AppChrome` fills the viewport instead of the source's fixed 900px height; the modal caps at 750px and shrinks below that. | The prototype has to hold up on whatever window the client opens it in. | Idea 1, all screens |
| 2026-09-06 | Sprint renumbered 2 → 3 across routes, folders and the registry. | The repo was one behind the client's numbering: their Sprint 2 was the filter-builder modal reviewed on 2 Sep. This work is Sprint 3. References to what the client saw in their Sprint 1 and Sprint 2 keep the original numbers. | Whole repo |
| 2026-09-06 | Idea 1 is reframed as the incumbent rather than a contender. Screens unchanged; `premise`, `rationale` and tags say it is the rejected baseline. | The alternatives need something concrete to be argued against, and the objections have to stay visible in the flow. | Idea 1 |
| 2026-09-06 | The applied-filter bar is `sticky` inside the scrolling content area. | The bar scrolled away with the table, which the real product would not do. | Idea 1 — applied, many-filters, group-by, filter-bar-dropdown |
| 2026-09-06 | Cascade popovers are flex columns with a capped height and an internally scrolling value list. | At fixed offsets they were clipped by the modal's `overflow-hidden` on windows shorter than ~800px. Unchanged at a normal window height. | Idea 1 — manual-attributes, manual-values, manual-selected, filter-bar-dropdown |
| 2026-09-06 | Explorer's back control routes explicitly to the index instead of calling `router.back()`. | A screen URL opened cold has no history, so the button did nothing visible. | Explorer |
| 2026-09-06 | Idea 3 built as a single editable sentence, not the multi-turn conversational refinement first specified. No transcript, no turns, no branching — natural language is read once and comes back as one line of English whose values, operators and joining words are all dropdowns. | Multi-turn narrowing is what the source AI tab already does, so building it would have re-argued the incumbent. The sentence tests the harder question instead: whether natural language can *be* the filter UI rather than sit beside it. The reversibility the original entry wanted survives as clause dismissal, value clearing and undo. | Idea 3 |
| 2026-09-06 | Idea 3's sixteen sample rows are filtered in memory against the sentence, and each row carries the attribute every clause tests. | Editing the sentence moved the count but not the table — remove Phase III and Phase III drugs stayed on screen. In a direction whose whole claim is that the sentence *is* the query, that reads as broken. Still no filter engine: a fixed array and a predicate. | Idea 3 — sentence |
| 2026-09-06 | Idea 4's widest record sits eleventh in the row order so the expanded detail band clears the open column menu. | The default frame had the popover on top of the detail band, so the two features the direction is arguing for obscured each other in the first thing a reviewer sees. | Idea 4 — grid |
| 2026-09-06 | Idea 2's filter panel shows two columns below a 1450px window instead of three, with the breadcrumb carrying the extra depth. | Three columns ellipsised the long labels — `Therapy Area / Indic…`, `Musculoskel…`. Two readable columns say more than three cramped ones, and the breadcrumb is already a live control. | Idea 2 — screener |
| 2026-09-06 | Idea 2's attribute column counts distinct values rather than drugs. | The drug count read 146 against nearly every attribute, which invites the question and answers nothing. Value counts vary and say how far an attribute can actually split the set. Free-text attributes carry an em dash. | Idea 2 — screener |
| 2026-09-06 | One shared `ProductChrome` replaces the four per-idea `AppChrome` components. Wordmark, area tabs, global search, notifications and account are now identical on every screen. | Each direction had invented its own header, with different entity lists and different labels. Shown in one session they read as three or four products rather than four proposals for one, which undercuts the comparison. | All ideas |
| 2026-09-06 | The canonical area list is the real product's eight — Companies, Drugs, Licensing Opportunities, Regulatory Milestones, Sales and Forecast, Drugs by Manufacturer, NPV, Advanced Company Watchlist. The invented five-item nav (Drugs / Companies / Deals / Clinical Trials / Reports) is gone. | Drugs is one of eight peers in the live platform. No second tier was added above them: inventing a product-level nav would repeat exactly the mistake being fixed. | All ideas |
| 2026-09-06 | The chrome is two rows — identity, search and account above; the eight areas below. | `Advanced Company Watchlist` is twenty-six characters. The eight areas will not sit inline beside a wordmark and a 264px search field without being abbreviated into names the product does not use. Idea 4 had already reached this layout independently. | All ideas |
| 2026-09-06 | The header search is a slot (`search`), not a fixed placeholder box. | One direction is going to argue that the platform's cross-entity natural-language search is good and cannot feed the screener. That argument has to be makeable by wiring the real field, not by drawing a second header. | All ideas |
| 2026-09-06 | Idea 1 keeps the shared chrome and passes `body="scroll"` rather than keeping a plainer header of its own. | Its plainness belongs below the chrome — the incumbent's filter bar and table — not in the shell. The shell is the same product in all four directions. Its filter chips keep the plainer look through `FilterPill variant="muted"`. | Idea 1 |
| 2026-09-06 | `StageBadge`, `FilterPill` and `OperatorWord` lifted to `src/components/prototype/`. Idea 3's interactive operator words, Idea 1's Boolean `OperatorPill` and Idea 4's `ValuePills` stay local. | The first three were drawn three or four times with small differences a client would read as inconsistency. The last three look similar but are load-bearing to one direction each; merging them would flatten what the directions are testing. | Ideas 1–4 |
| 2026-09-06 | Idea 1's results table still shows development stage as a plain cell, not a `StageBadge`. | It is a faithful port of the design being argued against; the incumbent's grid has no status badges. | Idea 1 |
| 2026-09-07 | Idea 3's sample grows from sixteen rows to seventy-eight, spread across ten therapy descriptors, twenty-one targets, all five molecule types and the whole pipeline from Discovery to Withdrawn; the value lists for Drug Descriptor, Target and ATC Classification grow with it, and the results table gains a Drug Descriptor column while losing its sort arrows. `screenDrugs` reconciles the count against the rows — no matching row means zero, and the count is floored at the number drawn. | The sixteen rows were one neighbourhood — generic anti-inflammatory ACTG2 small molecules — so any query outside it (`phase 3 oncology`, `monoclonal antibodies in preclinical`) produced a confident four-digit count above an empty table. In the direction whose whole argument is that the sentence can be trusted, a number the rows cannot corroborate is the first thing a sceptical reader finds. Every value in the sample is a canonical option, so everything visible in the table is also askable in the sentence. The sort arrows go because they did nothing, and their width is what lets eight columns fit a 1440px window without the horizontal scroll the incumbent is criticised for; the sortable grid is Idea 4's argument to make. | Idea 3 — start, sentence |
| 2026-09-07 | Idea 3's Development Stage values are listed in pipeline order — Discovery, Preclinical, Phase I–III, Pre-registration, Marketed, Withdrawn — rather than by descending count like the other attributes. `Marketed` and `Withdrawn` carry the noun in the sentence: `in the Marketed stage`. | A clause renders its values in its own option order, so `phase 1/2` resolved to the sentence "in Phase II or Phase I". Pipeline order is also how an analyst reads a stage. Separately, `in Marketed` and `in Withdrawn` read like a form field beside `in Phase II`, which undercuts the claim that the query is just English — the two values that are statuses rather than steps now carry their own noun. | Idea 3 |
